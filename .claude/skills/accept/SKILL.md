# /accept — приёмка по критериям Fable

Вход: $ARGUMENTS (пусто = HEAD, с начала текущего WORK LOCK).

1. **CI:** `node .claude/tools/evidence.mjs $ARGUMENTS --md`. `STATUS`:
   - `RUNNING` / `NO-CI-YET` — не PASS. Скажи, что ждёт, и не закрывай задачу.
   - `FAIL` — открой упавший шаг (`/ci`), найди первую настоящую ошибку.
   - `TESTED-CODE` — тесты прошли на этом SHA. Это не `VERIFIED-LIVE` и не `USER-CONFIRMED`.
2. **Красный → зелёный:** в отчёте должна быть строка упавшей ассерты *до* правки (по состоянию, не «функции нет»). Нет её в коммите — найди в истории сессии или прогоне на прошлом SHA (`CREW_CORE_SOURCE=<файл> node --test …`), иначе пиши «красный не зафиксирован».
3. **Соседний случай:** назови, какой рядом лежащий сценарий проверен (другая раса, другой уровень, пауза, второй игрок).
4. **Экипаж и графика:** если менялись `crew-core.js`, `crew-rig.js` или отрисовка экипажа — `BCM_QA_BROWSER_CHANNEL=msedge node tools/crew-lab/shoot.mjs`, посмотри кадры `.qa-artifacts/crew-lab/*.png` сам (Read) и опиши, что видно. Скриншоты — локальные, в репозиторий не коммитить.
5. **Итог** (по-русски, формат playbook §5):

```
STATUS: TESTED-CODE | RUNNING | FAIL
FILES: …
FINDINGS: что изменилось для игрока
TESTS: красный → зелёный; CI N/N со ссылками; Crew Lab — что видно
BLOCKERS: не проверено (живой сайт, ручная игра, телефон/геймпад)
RECOMMENDATION: следующий шаг одной строкой
```

Не выдавай уровень проверки сильнее фактического (AGENTS.md §2).
