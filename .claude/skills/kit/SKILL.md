# /kit — журнал комплектации

Вход: $ARGUMENTS

1. Прочитай `mini-sim/JOURNAL_KIT.md`: шапку с 11 категориями и раздел нужной мини-игры. Новых категорий не заводить без прямой просьбы владельца.
2. «Не хватает» — не ошибка кода. Поломку → `/bug`, хотелку без дыры в игре → `/idea`.
3. Проверь наличие ресурса в репозитории (Glob по `mini-sim/assets/**`, манифесты `mesh/manifest.json`, `ships/catalog.json`), прежде чем писать «нет». Укажи путь, если есть.
4. Правь ячейку таблицы раздела нужной мини-игры: `| Категория | Есть | Требует проверки | Не хватает |`. Строку на игру и категорию, без смешения.
5. Звук: AUDIO FREEZE — можно отметить, какой файл есть/нет, но не заказывать и не считать багом.
6. **При подъёме версии мини-игры:** каждую строку «Требует проверки» по ней перечитать на новой версии или пометить `stale (<старая версия>)`. `stale` — не очередь работ.
7. `зависимости` — стык «игра не работает без другой игры», не мост и не пустой ресурс.
8. Покажи изменённые строки владельцу.
