# /bug — журнал багов

Вход: $ARGUMENTS

1. **Фильтр.** Баг — только когда игра делает не то, что уже должна делать. Если это хотелка → `/idea`. Если нет модели/текстуры/звука → `/kit`. Красный live-QA walkingyog, незавершённый CI, «ещё не сделали» — не баги (см. шапку журнала). Если не баг — скажи, куда это идёт, и не пиши сюда.
2. Прочитай `mini-sim/JOURNAL_BUGS.md` целиком. Проверь, нет ли уже такой записи (в т.ч. в «Не баги»). Дубликат → дополни существующую свидетельством.
3. Сверь с кодом: найди место поиском по символам, укажи файл и функцию. Чтение кода — допустимая проверка, но не `CHECKED` для глаза игрока.
4. Новый номер = максимальный BUG-NNN + 1. Вставь перед разделом `## Не баги`.

Формат (все поля обязательны):

```markdown
## BUG-NNN — <короткое название>

- **Мини-игры:** <одна или несколько>.
- **Версия:** <Mini-Sim / Tower версия, `main` SHA>.
- **Категория:** <одна из 11 в JOURNAL_KIT.md>.
- **Воспроизведение:** <шаги>.
- **Ожидали:** <…>.
- **Получили:** <…>.
- **Проверка:** <что реально сделано: чтение файла@SHA / тест / браузер / слова владельца с временем>.
- **Статус:** `OPEN`.
```

Статусы: `OPEN` → `FIXED` (есть коммит, живая игра не подтверждена) → `CHECKED` (проверка на указанном SHA прошла) → `USER-CONFIRMED`. Плюс `stale` при подъёме версии без перечитывания. При смене статуса — добавь SHA/run, не стирай прежнее свидетельство.

5. Обнови строку «Срез чтения» только если действительно перечитал весь журнал на новом HEAD.
6. Покажи владельцу итоговую запись. Коммит — отдельным шагом writer'а (`docs(minisim): …`).
