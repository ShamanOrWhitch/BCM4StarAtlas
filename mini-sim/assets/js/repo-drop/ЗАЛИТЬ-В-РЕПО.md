# Как залить в репозиторий BCM4StarAtlas (ревизия 19)

Цель репозитория — `mini-sim/assets/js/deep-space-warp.js`.
Ничего больше трогать не нужно: остальные наши файлы (`warp_demo.html`, тесты,
`NOTES.md`) — вне игры.

## Вариант A. Готовым файлом (проще, 2 команды)

```bash
cd путь/к/BCM4StarAtlas
cp путь/к/repo-drop/mini-sim/assets/js/deep-space-warp.js mini-sim/assets/js/deep-space-warp.js
bash путь/к/replace/bump_version.sh .        # поднимает версию в 6 местах
```

## Вариант B. Патчем

Против чистого `main@40d8a7b2` — `warp_space.patch` (**+2687 / −45**);
против уже установленной ревизии 15 — `warp_patch_from_live.patch` (**+370 / −20**).

```bash
cd путь/к/BCM4StarAtlas
git apply --check warp_space.patch           # полный, от чистой 0.14.0
git apply         warp_space.patch
bash путь/к/replace/bump_version.sh .
```

Патч собран ровно против `mini-sim/assets/js/deep-space-warp.js` из `main@40d8a7b2`
(md5 `e5271ffb2b8e33f1cb1f162d6fd8dad6`, 308 087 байт) — это тот же файл, что
сейчас отдаёт живой сайт 0.14.0. Если патч не лег, значит база уже уехала:
берите вариант A, он от базы не зависит.

## Не забудьте бамп версии

Без бампа браузер отдаст закэшированный старый `deep-space-warp.js` и вы не
увидите ни 142 BPM, ни крена корабля. Скрипт `replace/bump_version.sh` поднимает
версию в `mini-sim/bcm-mini-sim.php` и `assets/js/mini-sim.js` (6 мест).

## Проверка после заливки (без моего участия)

1. Открыть `walkingyog.com/bcm4sa`, войти в варп.
2. В консоли: `BCMDeepSpaceWarpShipStats()` → `{ …, roll: …, manualRoll: 0 }`.
3. `BCMDeepSpaceWarpBgStats()` → `{ random: true, hold: 2, pool: 4, kind: … }`;
   переходы должны идти примерно каждые 2–4 с и каждый раз быть разными.
   `BCMDeepSpaceWarpSetRandomCycle(false)` возвращает тактовую сетку 142 BPM.
4. `BCMDeepSpaceWarpAddShipRoll(1.57)` → корабль лёг на борт на 90°.
5. Профиль «Пульс» на классе I: в консоли не должно быть `IndexSizeError`.
