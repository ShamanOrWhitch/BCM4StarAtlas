## 1. Основное (обязательно) — один файл

**Путь в репозитории:**

```
mini-sim/assets/js/deep-space-warp.js
```

Прямая ссылка на файл:
https://github.com/ShamanOrWhitch/BCM4StarAtlas/blob/main/mini-sim/assets/js/deep-space-warp.js

**Как положить (веб-интерфейс, без git):**

1. Открыть папку загрузки:
   https://github.com/ShamanOrWhitch/BCM4StarAtlas/upload/main/mini-sim/assets/js
2. Перетащить туда `repo-drop/mini-sim/assets/js/deep-space-warp.js`
   (имя файла менять не нужно — оно уже такое).
3. Commit message, например: `warp: ревизия 15 — случайный ритм ~2 с, 6 видов перехода, корабль сзади (Pearce F4), 142 BPM вторым режимом`.
4. Commit directly to `main` (или через PR — как принято в проекте; я в `main`
   не пишу).

**Как положить (git):**

```bash
cd путь/к/BCM4StarAtlas
cp путь/к/repo-drop/mini-sim/assets/js/deep-space-warp.js mini-sim/assets/js/deep-space-warp.js
git add mini-sim/assets/js/deep-space-warp.js
git commit -m "warp: ревизия 15 (случайный ритм ~2 с, 6 переходов, корабль сзади)"
```

**Или патчем. Два разных патча, выберите по состоянию файла в репозитории:**

```bash
# A. Если в репозитории/на сайте УЖЕ стоит наша ревизия 15 (md5 0f01b3fb…):
#    это патч только про дыры, +36 / −5 строк
cd путь/к/BCM4StarAtlas
git apply --check путь/к/warp_holes_fix.patch && git apply путь/к/warp_holes_fix.patch
git commit -am "warp: ревизия 16 — стенка без дыр (площадь панели)"

# B. Если файл всё ещё чистый 0.14.0 (md5 e5271ffb…): полный патч
git apply --check путь/к/warp_space.patch && git apply путь/к/warp_space.patch
git commit -am "warp: ревизии 8–16"
```

## 2. Версия (без этого не увидите изменений)

Ассеты подключаются как `?ver=<BCM_MINI_SIM_VERSION>`, поэтому старый файл
останется в кэше браузера. Поднимаются **6 мест в двух файлах**:

```
mini-sim/bcm-mini-sim.php            Version: 0.14.0, define('BCM_MINI_SIM_VERSION', '0.14.0'), строка «SPACE LABYRINTH — 0.14.0»
mini-sim/assets/js/mini-sim.js       «КОСМИЧЕСКИЙ ЛАБИРИНТ — 0.14.0», «SPACE LABYRINTH — 0.14.0», config.version || "0.14.0"
```

```bash
bash путь/к/replace/bump_version.sh 0.14.0 0.14.1     # из корня репозитория
```

Скрипт сам проверит, что до замены нашлось ровно по одному вхождению, поменяет,
проверит после и сделает `node --check`. Потом закоммитить оба файла.

## 3. Чего НЕ нужно класть (это не игра)

`warp_demo.html`, все `*.test.mjs`, `NOTES.md`, `build_*.py`, `warp_backdrop_core.js`
как отдельный файл — это стенд и проверки. Ядро уже вкомпилировано внутрь
`deep-space-warp.js`, отдельный файл в игре не подключается.

Обои-скетчи уже лежат в репозитории: `mini-sim/assets/scetchs/` (6 SVG).
Скрипт ищет их по пути `../scetchs/…` относительно `assets/js/`, то есть попадает
ровно туда. Если папку когда-нибудь уберут — варп сам уйдёт на процедурный фон,
ошибки не будет.

## 4. Проверка после заливки (5 команд в консоли на живом сайте)

```js
BCMDeepSpaceWarpBgStats()        // { random: true, hold: 2, pool: 4, kind: "…" }
BCMDeepSpaceWarpShipStats()      // { spec: "pearce-f4", size: 22…46, roll: …, manualRoll: 0 }
BCMDeepSpaceWarpAddShipRoll(1.57)   // корабль лёг на борт на 90°
BCMDeepSpaceWarpSetRandomCycle(false) // вернулась тактовая сетка 142 BPM
BCMDeepSpaceWarpGetTransition()  // текущий вид перехода
```

В консоли не должно быть `IndexSizeError` при виде «Пульс» и обратном ходе.
Стенка должна быть сплошной: в ревизии 16 починены «дыры» слева/справа
(целые сектора выбрасывались как субпиксельные).
