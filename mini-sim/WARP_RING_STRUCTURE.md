# Warp · астероидный лабиринт · Ring — что в каком файле

Проверено на `main` `a4bf459` (Mini-Sim `0.15.9`, Tower `0.2.88`), 16.11.2026.
Все номера строк — из этого HEAD, а не из памяти о прошлых версиях.

## Коротко

`mini-sim/assets/js/deep-space-warp.js` — **9370 строк, один файл**, и в нём четыре разные вещи, а не один генератор:

| Что | Где в файле | Мир / объект |
|---|---|---|
| 3D-лабиринт в астероиде (Space Labyrinth, вид от первого лица) | `2465` | `bcm-procedural-asteroid-maze` |
| Ring Frontier — большой 2D-платформер | `3429` функция `buildRingWorld()`, `3431` | `bcm-ring-frontier-side-scroll` |
| 2.5D-комната клетки того же лабиринта | `4118` | `bcm-asteroid-cell-room` |
| Труба Warp: фон, двери, переливы, аномалии, астероиды на стенке | IIFE `warpSpace` — `5913`; UI-оболочка `warpDevice` — `8220` | canvas-сцена Warp |

## Генератор лабиринта — один, и он внутри этого файла

- Сетка: `const NX = 7, NY = 3, NZ = 7, CELL = 6.8, WALL = 0.46` — строка `2382`.
- Проходка: **seeded depth-first carve** (комментарий `2427`: «Seeded depth-first carve guarantees a connected route through every level of the maze»).
- Вход `startNode = at(0,1,0)`, выход `exitNode = at(6,1,6)` — строки `2644-2645`.
- Состояние мира: объект `maze = { … }` со `seed`, `cells`, `walls`, `crystals`, `beacon`, `dimensions` — начало `2711`.
- Текстуры стен: `makeMazeTexture` — `2288`.

**Ключевая строка в самом коде** (в объекте `maze`, строка `2715`):

> `// The 2D Ring mode reuses this exact maze instance and topology, not a second RNG.`

То есть Ring — **не второй генератор**: он берёт ту же `maze`-инстанцию и ту же топологию. Один сид → один лабиринт → три вида: 3D-проход, 2.5D-комната, 2D-платформер. Именно поэтому 6 форм боссов попадают в Ring тем же сидом (`hashSeed(seed + "|boss-gate")`, строка `4246` в `0.15.9`), что и весь астероид.

## Что в этом файле НЕ лежит

| Что | Файл | Строк |
|---|---|---|
| Объёмное поле астероидов в трубе Warp (CPU-планировщик секторов) | `warp-sector-core.js` | 675 |
| Сцена этого поля (r128, восемь InstancedMesh-слотов) | `warp-sector-scene.js` | 832 |
| Hull Dive (затопление и сварка отсеков, открывается из астероидного кольца) | `hull-dive.js` | 1056 |
| Фон-обои трубы | `warp_backdrop_core.js` | 1861 |

Астероиды **на стенке трубы** (`warpAsteroids`, `warpAsteroidSeed` — из ваших патчей `c3006dd`/`97b77e5`) рисуются в `deep-space-warp.js`: строки `347-363` (состояние), `608-643` (плотность и план), `1059-1135` (загрузка GLB-шаблонов камня и кристалла), `2768` `attachAsteroidWallCrystals`.

## Как это связано по режимам

```
state.mode = "maze"                → 3D-лабиринт в астероиде         (2046, 3016, 3154)
state.ringPlatformer = true        → Ring Frontier (2D)              (129, 795 attemptOpenRingPlatformer)
E у светящегося люка               → смена этажа внутри лабиринта
R / LB                             → этаж, второй игрок, геймпад
```

Оба режима живут в одной `THREE`-сцене и одном цикле. Второй WebGL-контекст не создаётся — это прямо запрещено правилами проекта.

## Практический вывод

1. **Один файл — да, один генератор — нет.** Генератор лабиринта ровно один (7×3×7, seeded DFS) и он в `deep-space-warp.js`; Ring и 2.5D-комната — потребители его топологии, труба Warp — соседняя подсистема в том же файле.
2. **Правка боссов Ring = правка `deep-space-warp.js`** — того самого файла, который вы загружаете патчами «Add files via upload». Пока файл правится вами, любой мой патч туда конфликтен: нужен WORK LOCK и согласованный порядок.
3. **Ассеты боссов уже лежат отдельно** (`mini-sim/assets/ring-bosses/`) — то есть подключение шести форм заденет только этот файл, а не сборку плагина.
4. **Версии для сверки:** `BCM_MINI_SIM_VERSION = 0.15.9`, `BCM_TOWER_VERSION = 0.2.88`; маркер свежести дерева — `grep -c warpAnomalyVariant mini-sim/assets/js/deep-space-warp.js` (0 = дерево откатилось к `0.15.7`).
